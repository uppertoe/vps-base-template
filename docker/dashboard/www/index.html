Admin dashboard

Management surfaces for this server. Everything here sits behind the admin login.

How access works here
Staff access

For reading team information.

Anyone with an approved email address can get in: they receive a one-time code in their inbox, so there is no separate account or password to set up. Use this for the read-only pages the whole team should see.

You manage who is an admin, invite codes, and admin two-factor under Email login settings.

Named accounts

For apps people log into and change.

Some apps need a real account for each named person, with a password and an authenticator app, rather than just an email address. These are set up individually per person.

You create and remove these under User accounts; people look after their own password and two-factor under Sign-in & 2FA.

Rule of thumb: if a page just shows team information, staff access (email) covers it. If a page lets someone log in and change things, it needs a named account.

Protected by the admin login. Sessions end when you sign out.
